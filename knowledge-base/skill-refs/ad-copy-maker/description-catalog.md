# Description catalog

Patterns for the available description slots; start with two and add only useful supported copy. Which pattern belongs in which slot is in `composition.md`;
this page is about writing the sentence.

Source: Description Expansion Catalog and SOP – Write Compelling RSAs §2.

---

## The constraint

Ninety characters. The useful band is **75–90** (Description Quality Checklist, "most descriptions
75–90 characters"). Characters are counted the way the ad editor counts them.

Two rules govern everything below.

**Descriptions expand; they never restate.** A description that says what a headline already said in
other words has spent 90 characters on nothing. Headlines carry the claims; descriptions carry the
context, the specifics, the proof and the reassurance that do not fit in 30 characters.

**Put the ad group's core keyword in D1, naturally.** Google bolds text matching the query, and
bolding is visual prominence. Stuffed keywords read as stuffed and are worse than none.

---

## Two ways to expand

**Single-angle** — the description does one job: proof, or risk removal, or the offer. Clear, and
easy to compare across a cluster.

**Combined-angle** — the description stacks two or three jobs. Denser, and usually the right choice
at 90 characters.

---

## Single-angle patterns

| Job | Pattern |
|---|---|
| Problem / pain recognition | `[Tired of X?] + [we solve it]` · `[pain] + [what you get instead]` · `[symptom] + [outcome]` |
| Value proposition | `[outcome] + [how it works]` · `[outcome] + [without friction]` · `[what you get] + [result]` |
| USP / differentiation | `[unique approach] + [benefit]` · `[specialisation] + [outcome]` · `[comparison] + [advantage]` |
| Value boosters | `[what is included] + [why it matters]` · `[bonus] + [value]` |
| Social proof and authority | `[scale] + [outcome]` · `[rating] + [review count]` · `[credential] + [what it means]` |
| Risk removal | `[trial or guarantee] + [terms]` · `[cancel or return] + [no penalty]` · `[no obligation] + [reassurance]` |
| Call to action | `[CTA] + [ease]` · `[CTA] + [speed]` · `[CTA] + [incentive]` |

## Combined patterns

| Pattern | Shape | Belongs in |
|---|---|---|
| Problem + Solution | `[pain acknowledgment] + [your answer]` | D1 |
| Proof + Benefit, Proof + CTA | `[evidence] + [what that means for them]` | D2 |
| Benefit + Risk Removal | `[what you get] + [why it is safe to try]` | D3 |
| Risk + CTA | `[remove the hesitation] + [drive the action]` | D3 |
| Value Booster + CTA | `[what is included] + [how to get it]` | D4 |

D4 is used only for a documented expansion test. Its pattern follows the specific message gap.

---

## Urgency in D3

D3 takes an authentic deadline when one exists. When there is none, it is pure risk removal — an
invented deadline is a trust problem and a policy risk, and it will outlive the promotion it was
written for. A promotion the offer document marks as expired never appears.

---

## What disqualifies a description

From the Description Quality Checklist:

- It restates a headline instead of adding to it.
- It is a fragment, or its grammar and punctuation do not hold up.
- It is written about the advertiser rather than about the searcher.
- It leans on vague claims — "quality service", "great results" — with nothing specific behind them.
- It makes an unverifiable superlative or a policy-risk claim.
- It carries no evidence anywhere in the set: at least one description must carry a number, a
  rating or a credential.
- It is over 90 characters.

---

## Coverage across the four

Taken together, the selected descriptions must:

- carry at least two distinct angles — not four variations on one theme;
- include risk reduction somewhere (a trial, a return, a refund, no obligation);
- include a clear next step somewhere;
- mix problem-and-solution language with aspirational value language;
- include at least one piece of evidence — a number, a rating, a credential.
